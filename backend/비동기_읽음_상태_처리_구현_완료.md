# 비동기 읽음 상태 처리 구현 완료 ✅

## 📋 구현 개요

채팅 메시지의 읽음 상태 업데이트와 알림 전송 로직을 **비동기 이벤트 방식**으로 구현하여 응답 시간을 개선했습니다.

---

## 🎯 구현 목표

1. ✅ 메시지 읽음 처리를 비동기로 처리하여 응답 시간 단축
2. ✅ 읽음 상태 업데이트 후 실시간으로 unreadCount 재계산 및 브로드캐스트
3. ✅ 알림 전송 로직 통합 (선택적)
4. ✅ 비동기 처리 아키텍처 완성

### 2. **MessageReadEventListener.java** (구현 완료)
- TODO 주석을 제거하고 실제 로직 구현
- 비동기 처리 (`@Async("asyncTaskExecutor")`)
- 트랜잭션 관리 (`@Transactional`)

**위치:** `backend/src/main/java/com/goodee/coreconnect/chat/event/MessageReadEventListener.java`

**구현 내용:**
1. 읽음 상태 업데이트 (`ChatMessageReadStatusRepository.updateReadStatus()`)
2. unreadCount 재계산 (`countUnreadByChatId()`)
3. Chat 엔티티의 unreadCount 업데이트
4. WebSocket을 통한 실시간 브로드캐스트
5. 알림 전송 로직 (주석 처리, 필요시 활성화 가능)

```java
@Async("asyncTaskExecutor")
@EventListener
@Transactional
public void handle(MessageReadEvent event) {
    // 1. 읽음 상태 업데이트
    int updatedCount = readStatusRepo.updateReadStatus(
            event.getUserId(), 
            event.getMessageId(), 
            LocalDateTime.now()
    );

    if (updatedCount > 0) {
        // 2. unreadCount 재계산
        int newUnreadCount = readStatusRepo.countUnreadByChatId(event.getMessageId());
        
        // 3. Chat 엔티티 업데이트
        chatRepository.findById(event.getMessageId()).ifPresent(chat -> {
            chat.updateUnreadCount(newUnreadCount);
            chatRepository.save(chat);
        });

        // 4. 실시간 브로드캐스트
        String topic = "/topic/chat.room." + event.getRoomId() + ".unreadCount";
        messagingTemplate.convertAndSend(topic, Map.of(
                "messageId", event.getMessageId(),
                "unreadCount", newUnreadCount,
                "readBy", event.getUserId()
        ));
    }
}
```

## 🏗️ 아키텍처 흐름

```
[클라이언트 요청]
    ↓
[ChatMessageController.markSingleMessageAsRead()]
    ↓ (즉시 응답 반환)
    ├─ ResponseEntity.ok() → 클라이언트
    └─ ChatService.markAsRead()
        ↓
    [MessageReadEvent 발행]
        ↓
    [MessageReadEventListener.handle()] (@Async)
        ├─ 1. 읽음 상태 업데이트 (DB)
        ├─ 2. unreadCount 재계산 (DB)
        ├─ 3. Chat 엔티티 업데이트 (DB)
        └─ 4. WebSocket 브로드캐스트 (실시간 알림)
```

## 🔧 비동기 설정 (이미 완료)

**위치:** `backend/src/main/java/com/goodee/coreconnect/config/AsyncConfig.java`

```java
@Configuration
@EnableAsync
public class AsyncConfig {
    @Bean(name = "asyncTaskExecutor")
    public Executor asyncTaskExecutor() {
        ThreadPoolTaskExecutor exec = new ThreadPoolTaskExecutor();
        exec.setCorePoolSize(4);
        exec.setMaxPoolSize(8);
        exec.setQueueCapacity(100);
        exec.setThreadNamePrefix("async-");
        exec.initialize();
        return exec;
    }
}
```

## 🚀 추가 개선 가능 사항

### 1. 알림 전송 로직 활성화
`MessageReadEventListener.java`의 주석 처리된 부분을 활성화하여 "A님이 메시지를 읽었습니다" 알림을 전송할 수 있습니다.

```java
// MessageReadEventListener.java (line 86-106)
notificationService.sendNotification(
        chat.getSender().getId(),
        NotificationType.CHAT,
        "메시지가 읽혔습니다",
        event.getMessageId(),
        event.getRoomId(),
        event.getUserId(),
        null,
        null
);
```

### 2. Redis 캐시 추가
unreadCount를 Redis에 캐시하여 DB 조회 횟수를 줄일 수 있습니다.

### 3. 배치 처리 최적화
여러 메시지를 한번에 읽음 처리할 때 각 메시지마다 이벤트를 발행하는 대신, 배치 이벤트를 발행하여 성능을 더욱 개선할 수 있습니다.

## 📌 주의사항

1. **트랜잭션 관리**: `MessageReadEventListener`는 별도의 트랜잭션에서 실행됩니다 (`@Async` + `@Transactional`).
2. **에러 처리**: 비동기 처리 중 에러가 발생해도 클라이언트는 이미 응답을 받았으므로, 에러는 로그로만 기록됩니다.
3. **이벤트 순서**: 여러 이벤트가 동시에 발행되면 처리 순서가 보장되지 않을 수 있습니다.
4. **스레드 풀 크기**: `AsyncConfig`의 스레드 풀 크기를 부하에 맞게 조정해야 합니다.
