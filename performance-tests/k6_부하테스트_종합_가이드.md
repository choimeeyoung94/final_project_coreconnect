## 개요

### 목적
CoreConnect 프로젝트의 채팅, 알림, 이메일 기능에 대한 부하 테스트를 수행하여 성능을 측정하고 개선점을 파악합니다.

### 테스트 도구
- **k6**: Grafana에서 개발한 오픈소스 부하 테스트 도구
- **언어**: JavaScript
- **프로토콜**: HTTP/REST, WebSocket (STOMP, 일반 WebSocket)

### 테스트 대상 기능
1. **채팅 기능**
   - REST API: 채팅방 생성, 메시지 전송/조회, 미읽은 메시지 개수
   - WebSocket STOMP: 실시간 메시지 송수신

2. **알림 기능**
   - REST API: 알림 조회, 읽음 처리, 알림 전송
   - WebSocket: 실시간 알림 수신

3. **이메일 기능**
   - REST API: 이메일 발송, 받은메일함/보낸메일함 조회
   - 임시저장, 휴지통, 중요 메일 관리

## 성능 테스트 시나리오

### 시나리오 1: Smoke Test (스모크 테스트)

**목적**: 시스템이 기본적으로 작동하는지 빠르게 확인

**설정**:
```javascript
smoke: {
  executor: 'constant-vus',
  vus: 5,
  duration: '1m',
}
```

**VU 패턴**:
```
VU
5  |████████████████████████████████
   |
0  |________________________________
   0                               1분
```

**사용 시기**:
- 새로운 코드 배포 후
- 설정 변경 후
- 부하 테스트 전 사전 검증

### 시나리오 2: Load Test (부하 테스트)

**목적**: 예상되는 정상 부하에서 성능 측정

**설정**:
```javascript
load: {
  executor: 'ramping-vus',
  startVUs: 0,
```

#### 5.2 WebSocket 세션 관리

```java
@Component
public class ChatWebSocketHandler extends TextWebSocketHandler {

    // 사용자별 세션 관리 (ConcurrentHashMap 사용)
    private final Map<Long, List<WebSocketSession>> userSessions = new ConcurrentHashMap<>();

    @Override
    public void afterConnectionEstablished(WebSocketSession session) throws Exception {
        Long userId = extractUserId(session);
        userSessions.computeIfAbsent(userId, k -> new CopyOnWriteArrayList<>()).add(session);
        log.info("WebSocket 연결: userId={}, sessionId={}", userId, session.getId());
    }

    @Override
    public void afterConnectionClosed(WebSocketSession session, CloseStatus status) throws Exception {
        Long userId = extractUserId(session);

        // ✅ 메모리 누수 방지: 세션 정리
        List<WebSocketSession> sessions = userSessions.get(userId);
        if (sessions != null) {
            sessions.remove(session);
            if (sessions.isEmpty()) {
                userSessions.remove(userId);
            }
        }

        log.info("WebSocket 연결 해제: userId={}, sessionId={}", userId, session.getId());
    }

    // 메시지 브로드캐스트 최적화
    public void sendToUser(Long userId, String message) {
        List<WebSocketSession> sessions = userSessions.get(userId);
        if (sessions != null) {
            // 병렬 스트림으로 여러 세션에 동시 전송
            sessions.parallelStream()
                .filter(WebSocketSession::isOpen)
                .forEach(session -> {
                    try {
                        session.sendMessage(new TextMessage(message));
                    } catch (IOException e) {
                        log.error("메시지 전송 실패: sessionId={}", session.getId(), e);
                    }
                });
        }
    }
}
```

### 6. 페이징 최적화

#### 6.1 커서 기반 페이징

**Offset 기반 페이징의 문제점**:
```sql
-- 10,000번째 페이지 조회 시 10,000개 row를 건너뛰어야 함 (느림!)
```

**커서 기반 페이징 (빠름)**:
```java

public interface EmailRepository extends JpaRepository<Email, Long> {

    // 첫 페이지
    @Query("SELECT e FROM Email e WHERE e.emailFolder = :folder ORDER BY e.emailSentTime DESC")
    List<Email> findFirstPage(@Param("folder") String folder, Pageable pageable);

    // 다음 페이지 (커서 기반)
    @Query("SELECT e FROM Email e WHERE e.emailFolder = :folder " +
           "AND e.emailSentTime < :cursor ORDER BY e.emailSentTime DESC")
    List<Email> findNextPage(@Param("folder") String folder,
                             @Param("cursor") LocalDateTime cursor,
                             Pageable pageable);
}
```

**Service 구현**:
```java
@Service
public class EmailServiceImpl implements EmailService {

    public EmailPageDTO getInbox(LocalDateTime cursor, int size) {
        Pageable pageable = PageRequest.of(0, size);

        List<Email> emails;
        if (cursor == null) {
            // 첫 페이지
            emails = emailRepository.findFirstPage("INBOX", pageable);
        } else {
            // 다음 페이지 (커서 사용)
            emails = emailRepository.findNextPage("INBOX", cursor, pageable);
        }

        // 다음 페이지를 위한 커서
        LocalDateTime nextCursor = emails.isEmpty() ? null :
            emails.get(emails.size() - 1).getEmailSentTime();

        return new EmailPageDTO(emails, nextCursor);
    }
}
```

```java
@Aspect
@Component
@Slf4j
public class PerformanceLoggingAspect {

    @Around("@annotation(PerformanceLog)")
    public Object logPerformance(ProceedingJoinPoint joinPoint) throws Throwable {
        String className = joinPoint.getTarget().getClass().getSimpleName();
        String methodName = joinPoint.getSignature().getName();

        long startTime = System.currentTimeMillis();

        try {
            Object result = joinPoint.proceed();
            return result;
        } catch (Exception e) {
            log.error("[METRICS] {}.{}() error type={}", className, methodName, e.getClass().getSimpleName());
            throw e;
        } finally {
            long duration = System.currentTimeMillis() - startTime;

            // 성능 메트릭 로깅
            log.info("[METRICS] {}.{}() duration={}ms", className, methodName, duration);

            // 느린 쿼리 경고 (1초 이상)
            if (duration > 1000) {
                log.warn("[SLOW] {}.{}() took {}ms", className, methodName, duration);
            }
        }
    }
}
```

| **TPS (Transactions Per Second)** | 초당 트랜잭션 수 |
| **Throughput** | 처리량. 단위 시간당 처리한 요청 수 |
| **Latency** | 지연시간. 요청부터 응답까지 걸린 시간 |
| **P95** | 95 percentile. 95%의 요청이 이 값 이내 |
| **P99** | 99 percentile. 99%의 요청이 이 값 이내 |
| **Check** | 테스트 내에서 성공/실패를 확인하는 검증 로직 |
| **Threshold** | 임계값. 테스트 성공 기준 |
| **Ramp-up** | 부하를 점진적으로 증가시키는 것 |
| **Ramp-down** | 부하를 점진적으로 감소시키는 것 |

2. **부하 테스트 실행** (16분 x 3 = 48분)
   - 채팅, 알림, 이메일 각각 테스트
   - 성능 지표 수집 및 분석

3. **성능 개선 작업** (필요 시)
   - 데이터베이스 인덱스 추가
   - 캐싱 적용
   - 비동기 처리

4. **개선 후 재테스트**
   - Before/After 비교
   - 개선 효과 확인

5. **스트레스 테스트** (선택적, 24분)
   - 시스템의 한계점 파악
   - 용량 계획 수립
