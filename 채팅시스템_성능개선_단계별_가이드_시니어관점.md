### 1.2 병목 구간 분석 (시니어 관점)

#### 병목 1: WebSocket 연결 관리 (C10K 문제)
```java
문제:
- 단일 JVM 프로세스당 최대 동시 연결: ~10,000개
- Tomcat 기본 Thread Pool: 200개
- Heap Memory 부족 시 GC Pause 급증

해결 필요:
- Thread Pool 튜닝
- Netty 기반 비동기 I/O
- Connection Pool 최적화
```

#### 병목 2: 메시지 브로드캐스팅
```java
현재 코드 (동기 처리):
messagingTemplate.convertAndSend(topic, message);
// 10,000명 → 10,000번 순차 전송 → 약 1-2초 소요

문제점:
1. 동기 방식으로 순차 전송
2. 단일 서버에서 모든 사용자에게 전송 불가능
3. 메모리 버퍼 오버플로우 위험
```

#### 병목 3: 데이터베이스 쓰기 경합
```sql
초당 1,000건 메시지 발생 시:
- INSERT: 1,000 TPS
- 읽음 상태 UPDATE: 10,000 TPS (10명 참여 채팅방 기준)
- 총 부하: 11,000 TPS

MySQL 단일 인스턴스 한계:
- 일반 HDD: ~500 TPS
- SSD: ~5,000 TPS
- NVMe: ~10,000 TPS
→ NVMe를 써도 한계 근접!
```

```java
// WebSocketConfig.java
@Configuration
public class WebSocketConfig implements WebSocketMessageBrokerConfigurer {
    
    @Override
    public void configureMessageBroker(MessageBrokerRegistry registry) {
        // ⭐ Task Executor 설정
        ThreadPoolTaskScheduler scheduler = new ThreadPoolTaskScheduler();
        scheduler.setPoolSize(Runtime.getRuntime().availableProcessors() * 2);
        scheduler.setThreadNamePrefix("ws-scheduler-");
        scheduler.initialize();
        
        registry.enableSimpleBroker("/topic", "/queue")
                .setTaskScheduler(scheduler)
                .setHeartbeatValue(new long[]{10000, 10000}); // 10초마다 heartbeat
        
        registry.setApplicationDestinationPrefixes("/app");
    }
    
    @Bean
    public ThreadPoolTaskExecutor asyncExecutor() {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        executor.setCorePoolSize(100);  // 기본 스레드
        executor.setMaxPoolSize(500);   // 최대 스레드
        executor.setQueueCapacity(1000); // 대기 큐
        executor.setThreadNamePrefix("async-");
        executor.setRejectedExecutionHandler(new ThreadPoolExecutor.CallerRunsPolicy());
        executor.initialize();
        return executor;
    }
}
```

```java
// ChatMessagePublisher.java
@Service
@RequiredArgsConstructor
@Slf4j
public class ChatMessagePublisher {
    
    private final RedisTemplate<String, Object> redisTemplate;
    private final ChatRepository chatRepository;
    
    /**
     * ⭐ 비동기 메시지 발행 (DB 저장과 분리)
     */
    @Async("asyncExecutor")
    public CompletableFuture<Void> publishMessageAsync(Integer roomId, ChatMessage message) {
        return CompletableFuture.runAsync(() -> {
            try {
                String channel = "chat:room:" + roomId;
                
                // Redis Pub/Sub로 발행 (평균 3-5ms)
                redisTemplate.convertAndSend(channel, message);
                
                log.info("[Publisher] 메시지 발행 완료 - channel: {}, messageId: {}", 
                        channel, message.getId());
                        
            } catch (Exception e) {
                log.error("[Publisher] 메시지 발행 실패 - roomId: {}", roomId, e);
            }
        });
    }
    
    /**
     * ⭐ 배치 발행 (성능 최적화)
     */
    public void publishBatch(Integer roomId, List<ChatMessage> messages) {
        if (messages.isEmpty()) return;
        
        String channel = "chat:room:" + roomId;
        
        // Pipeline으로 한 번에 전송
        redisTemplate.executePipelined((RedisCallback<Object>) connection -> {
            messages.forEach(msg -> {
                byte[] channelBytes = channel.getBytes();
                byte[] messageBytes = serialize(msg);
                connection.publish(channelBytes, messageBytes);
            });
            return null;
        });
        
        log.info("[Publisher] 배치 발행 완료 - channel: {}, count: {}", 
                channel, messages.size());
    }
}
```

#### 2.1.3 Subscriber 구현 (메시지 수신)

```java
// ChatMessageSubscriber.java
@Component
@RequiredArgsConstructor
@Slf4j
public class ChatMessageSubscriber {
    
    private final SimpMessagingTemplate messagingTemplate;
    private final WebSocketSessionManager sessionManager;
    private final ObjectMapper objectMapper;
    
    /**
     * ⭐ Redis Pub/Sub 메시지 수신
     * 중요: 이 메서드는 Redis가 호출하므로 빠르게 처리해야 함!
     */
    public void onMessage(String channel, ChatMessage message) {
        try {
            Integer roomId = extractRoomId(channel);
            
            // ⭐ 현재 서버에 연결된 사용자만 필터링
            Set<Integer> connectedUserIds = sessionManager.getConnectedUsers(roomId);
            
            if (connectedUserIds.isEmpty()) {
                log.debug("[Subscriber] 연결된 사용자 없음 - roomId: {}", roomId);
                return;
            }
            
            // ⭐ 병렬 스트림으로 동시 전송 (중요!)
            connectedUserIds.parallelStream().forEach(userId -> {
                try {
                    String destination = "/queue/chat.room." + roomId;
                    messagingTemplate.convertAndSendToUser(
                        String.valueOf(userId), 
                        destination, 
                        message
                    );
                } catch (Exception e) {
                    log.error("[Subscriber] 메시지 전송 실패 - userId: {}", userId, e);
                }
            });
            
            log.info("[Subscriber] 브로드캐스트 완료 - roomId: {}, users: {}", 
                    roomId, connectedUserIds.size());
                    
        } catch (Exception e) {
            log.error("[Subscriber] 메시지 처리 실패 - channel: {}", channel, e);
        }
    }
    
    private Integer extractRoomId(String channel) {
        // "chat:room:123" → 123
        return Integer.parseInt(channel.substring("chat:room:".length()));
    }
}
```

#### 2.1.4 Session Manager 구현

```java
// WebSocketSessionManager.java
@Component
@Slf4j
public class WebSocketSessionManager {
    
    // roomId → Set<userId> (현재 서버에 연결된 사용자)
    private final ConcurrentHashMap<Integer, Set<Integer>> roomSessions = new ConcurrentHashMap<>();
    
    // userId → sessionId
    private final ConcurrentHashMap<Integer, String> userSessions = new ConcurrentHashMap<>();
    
    /**
     * ⭐ 세션 등록
     */
    public void addSession(Integer userId, Integer roomId, String sessionId) {
        roomSessions.computeIfAbsent(roomId, k -> ConcurrentHashMap.newKeySet())
                    .add(userId);
        userSessions.put(userId, sessionId);
        
        log.info("[SessionManager] 세션 등록 - userId: {}, roomId: {}, sessionId: {}", 
                userId, roomId, sessionId);
    }
    
    /**
     * ⭐ 세션 제거
     */
    public void removeSession(Integer userId, Integer roomId) {
        Set<Integer> users = roomSessions.get(roomId);
        if (users != null) {
            users.remove(userId);
            if (users.isEmpty()) {
                roomSessions.remove(roomId);
            }
        }
        userSessions.remove(userId);
        
        log.info("[SessionManager] 세션 제거 - userId: {}, roomId: {}", userId, roomId);
    }
    
    /**
     * ⭐ 연결된 사용자 조회
     */
    public Set<Integer> getConnectedUsers(Integer roomId) {
        return roomSessions.getOrDefault(roomId, Collections.emptySet());
    }
    
    /**
     * ⭐ 통계 정보
     */
    public Map<String, Object> getStats() {
        return Map.of(
            "totalRooms", roomSessions.size(),
            "totalUsers", userSessions.size(),
            "roomDetails", roomSessions.entrySet().stream()
                .collect(Collectors.toMap(
                    Map.Entry::getKey,
                    e -> e.getValue().size()
                ))
        );
    }
}
```

### 📌 Phase 2: Kafka 도입 (10,000 → 50,000명)

**목표**: 메시지 영속성 보장 및 순서 보장

#### 2.2.1 Redis vs Kafka 비교 (시니어 관점)

```
Redis Pub/Sub:
✅ 장점: 초저지연 (3-5ms)
❌ 단점: 메모리 기반, 재시작 시 소실, 순서 보장 없음

Kafka:
✅ 장점: 디스크 기반, 영속성, 순서 보장, 재처리 가능
❌ 단점: 상대적으로 높은 지연 (50-100ms)

결론: Redis + Kafka 조합 사용
- Redis: 실시간 전달 (Primary)
- Kafka: 영속성 백업 (Secondary)
```

```java
// ChatMessageKafkaConsumer.java
@Component
@RequiredArgsConstructor
@Slf4j
public class ChatMessageKafkaConsumer {
    
    private final ChatRepository chatRepository;
    private final SimpMessagingTemplate messagingTemplate;
    
    /**
     * ⭐ Kafka 메시지 수신 (배치 처리)
     * 용도: 1) 백업 2) 장애 복구 3) 분석
     */
    @KafkaListener(
        topics = "chat-messages",
        groupId = "chat-consumer-group",
        containerFactory = "kafkaListenerContainerFactory"
    )
    public void consumeMessages(List<ConsumerRecord<String, ChatMessage>> records) {
        try {
            log.info("[KafkaConsumer] 배치 수신 - count: {}", records.size());
            
            // ⭐ 배치 처리 (성능 최적화)
            List<ChatMessage> messages = records.stream()
                    .map(ConsumerRecord::value)
                    .collect(Collectors.toList());
            
            // 1. DB 영속화 (배치 INSERT)
            saveBatch(messages);
            
            // 2. 읽음 상태 초기화 (비동기)
            initializeReadStatus(messages);
            
            log.info("[KafkaConsumer] 배치 처리 완료 - count: {}", messages.size());
            
        } catch (Exception e) {
            log.error("[KafkaConsumer] 배치 처리 실패", e);
        }
    }
    
    @Transactional
    private void saveBatch(List<ChatMessage> messages) {
        // JPA Batch INSERT
        messages.forEach(msg -> {
            // Redis에 이미 저장되었으므로, 여기서는 로깅용
            log.debug("[KafkaConsumer] 메시지 백업 - messageId: {}", msg.getId());
        });
    }
    
    @Async
    private void initializeReadStatus(List<ChatMessage> messages) {
        // 읽음 상태 초기화 (비동기 처리)
    }
}
```

### 3.2 Redis 캐싱 전략

```java
// RedisCacheService.java
@Service
@RequiredArgsConstructor
@Slf4j
public class RedisCacheService {
    
    private final RedisTemplate<String, Object> redisTemplate;
    
    /**
     * ⭐ 채팅방 메시지 캐싱 (최근 100개)
     */
    public void cacheRecentMessages(Integer roomId, List<ChatMessage> messages) {
        String key = "chat:room:" + roomId + ":recent";
        
        // ⭐ Sorted Set 사용 (시간순 정렬)
        ZSetOperations<String, Object> zset = redisTemplate.opsForZSet();
        
        messages.forEach(msg -> {
            double score = msg.getTimestamp();  // timestamp를 score로
            zset.add(key, msg, score);
        });
        
        // ⭐ 최근 100개만 유지
        zset.removeRange(key, 0, -101);
        
        // ⭐ TTL 설정 (24시간)
        redisTemplate.expire(key, 24, TimeUnit.HOURS);
    }
    
    /**
     * ⭐ 최근 메시지 조회 (캐시 우선)
     */
    public List<ChatMessage> getRecentMessages(Integer roomId, int count) {
        String key = "chat:room:" + roomId + ":recent";
        
        ZSetOperations<String, Object> zset = redisTemplate.opsForZSet();
        
        // ⭐ 최신순으로 조회
        Set<Object> messages = zset.reverseRange(key, 0, count - 1);
        
        return messages.stream()
                .map(obj -> (ChatMessage) obj)
                .collect(Collectors.toList());
    }
    
    /**
     * ⭐ 읽음 상태 캐싱
     */
    public void cacheReadStatus(Integer roomId, Integer userId, Set<Integer> readMessageIds) {
        String key = String.format("chat:read:%d:%d", roomId, userId);
        
        // ⭐ Bitmap 사용 (메모리 효율적)
        readMessageIds.forEach(messageId -> {
            redisTemplate.opsForValue().setBit(key, messageId, true);
        });
        
        // ⭐ TTL 설정 (7일)
        redisTemplate.expire(key, 7, TimeUnit.DAYS);
    }
}
```
