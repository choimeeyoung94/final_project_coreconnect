## 2. AWS 인프라 구성

### 2.1 VPC 및 서브넷 생성

```bash
# VPC 생성 (eksctl이 자동 생성하지만, 수동 생성 시)
aws ec2 create-vpc --cidr-block 10.0.0.0/16 --tag-specifications 'ResourceType=vpc,Tags=[{Key=Name,Value=chat-vpc}]'

# 변수 설정
VPC_ID="vpc-xxxxxxxxx"  # 위에서 생성된 VPC ID

# 퍼블릭 서브넷 (ALB용)
aws ec2 create-subnet --vpc-id $VPC_ID --cidr-block 10.0.1.0/24 --availability-zone ap-northeast-2a --tag-specifications 'ResourceType=subnet,Tags=[{Key=Name,Value=chat-public-2a}]'
aws ec2 create-subnet --vpc-id $VPC_ID --cidr-block 10.0.2.0/24 --availability-zone ap-northeast-2b --tag-specifications 'ResourceType=subnet,Tags=[{Key=Name,Value=chat-public-2b}]'
aws ec2 create-subnet --vpc-id $VPC_ID --cidr-block 10.0.3.0/24 --availability-zone ap-northeast-2c --tag-specifications 'ResourceType=subnet,Tags=[{Key=Name,Value=chat-public-2c}]'

# 프라이빗 서브넷 (노드용)
aws ec2 create-subnet --vpc-id $VPC_ID --cidr-block 10.0.11.0/24 --availability-zone ap-northeast-2a --tag-specifications 'ResourceType=subnet,Tags=[{Key=Name,Value=chat-private-2a}]'
aws ec2 create-subnet --vpc-id $VPC_ID --cidr-block 10.0.12.0/24 --availability-zone ap-northeast-2b --tag-specifications 'ResourceType=subnet,Tags=[{Key=Name,Value=chat-private-2b}]'
aws ec2 create-subnet --vpc-id $VPC_ID --cidr-block 10.0.13.0/24 --availability-zone ap-northeast-2c --tag-specifications 'ResourceType=subnet,Tags=[{Key=Name,Value=chat-private-2c}]'

# Internet Gateway
aws ec2 create-internet-gateway --tag-specifications 'ResourceType=internet-gateway,Tags=[{Key=Name,Value=chat-igw}]'
IGW_ID="igw-xxxxxxxxx"
aws ec2 attach-internet-gateway --vpc-id $VPC_ID --internet-gateway-id $IGW_ID

# NAT Gateway (프라이빗 서브넷 인터넷 접속용)
# EIP 생성
aws ec2 allocate-address --domain vpc --tag-specifications 'ResourceType=elastic-ip,Tags=[{Key=Name,Value=chat-nat-eip}]'
EIP_ALLOC_ID="eipalloc-xxxxxxxxx"

# NAT Gateway 생성 (퍼블릭 서브넷에 배치)
aws ec2 create-nat-gateway --subnet-id subnet-public-2a-id --allocation-id $EIP_ALLOC_ID --tag-specifications 'ResourceType=nat-gateway,Tags=[{Key=Name,Value=chat-nat}]'
```

**💡 Tip**: eksctl 사용 시 VPC는 자동 생성되므로 수동 생성은 선택사항입니다.

## 3. EKS 클러스터 생성

### 3.1 eksctl로 클러스터 생성 (권장)

```bash
# 클러스터 구성 파일 생성
cat > cluster-config.yaml <<EOF
apiVersion: eksctl.io/v1alpha5
kind: ClusterConfig

metadata:
  name: chat-prod
  region: ap-northeast-2
  version: "1.29"

# VPC 설정 (기존 VPC 사용 시)
# vpc:
#   id: "vpc-xxxxxxxxx"
#   subnets:
#     private:
#       ap-northeast-2a: { id: subnet-xxxxxxxxx }
#       ap-northeast-2b: { id: subnet-xxxxxxxxx }
#       ap-northeast-2c: { id: subnet-xxxxxxxxx }

# 노드 그룹 (10대 시작, 최대 50대)
managedNodeGroups:
  - name: ng-chat-core
    instanceType: m6i.xlarge  # 4vCPU, 16GB RAM
    desiredCapacity: 10
    minSize: 10
    maxSize: 50
    volumeSize: 100
    privateNetworking: true
    labels:
      role: chat-backend
    tags:
      k8s.io/cluster-autoscaler/enabled: "true"
      k8s.io/cluster-autoscaler/chat-prod: "owned"
    iam:
      withAddonPolicies:
        autoScaler: true
        cloudWatch: true
        ebs: true
        efs: true

# CloudWatch 로깅
cloudWatch:
  clusterLogging:
    enableTypes: ["*"]

# IAM OIDC Provider (IRSA용)
iam:
  withOIDC: true
EOF

# 클러스터 생성 (15~20분 소요)
eksctl create cluster -f cluster-config.yaml

# kubeconfig 설정
aws eks update-kubeconfig --region ap-northeast-2 --name chat-prod

# 클러스터 확인
kubectl get nodes
kubectl get ns
```

### 5.3 애플리케이션 코드 최적화 (웹소켓 예시)

```javascript
// server.js
const express = require('express');
const http = require('http');
const socketIo = require('socket.io');
const Redis = require('ioredis');
const { createAdapter } = require('@socket.io/redis-adapter');

const app = express();
const server = http.createServer(app);

// Redis 연결 (ElastiCache)
const pubClient = new Redis({
  host: process.env.REDIS_HOST || 'localhost',
  port: process.env.REDIS_PORT || 6379,
  password: process.env.REDIS_PASSWORD,
  retryStrategy: (times) => Math.min(times * 50, 2000),
});

const subClient = pubClient.duplicate();

// Socket.IO 설정
const io = socketIo(server, {
  cors: { origin: '*' },
  transports: ['websocket', 'polling'],
  pingTimeout: 60000,
  pingInterval: 25000,
});

// Redis Adapter (클러스터 간 메시지 동기화)
io.adapter(createAdapter(pubClient, subClient));

// 헬스체크 엔드포인트
app.get('/health', (req, res) => {
  res.status(200).json({ status: 'ok', timestamp: Date.now() });
});

app.get('/ready', async (req, res) => {
  try {
    await pubClient.ping();
    res.status(200).json({ status: 'ready' });
  } catch (err) {
    res.status(503).json({ status: 'not ready', error: err.message });
  }
});

// 소켓 연결 처리
io.on('connection', (socket) => {
  console.log(`User connected: ${socket.id}`);

  socket.on('join-room', (roomId) => {
    socket.join(roomId);
    socket.to(roomId).emit('user-joined', socket.id);
  });

  socket.on('chat-message', (data) => {
    io.to(data.roomId).emit('chat-message', {
      userId: socket.id,
      message: data.message,
      timestamp: Date.now(),
    });
  });

  socket.on('disconnect', () => {
    console.log(`User disconnected: ${socket.id}`);
  });
});

const PORT = process.env.PORT || 3000;
server.listen(PORT, () => {
  console.log(`Chat server running on port ${PORT}`);
  console.log(`Redis connected to ${process.env.REDIS_HOST}`);
});

// Graceful shutdown
process.on('SIGTERM', () => {
  console.log('SIGTERM received, closing server...');
  server.close(() => {
    pubClient.quit();
    subClient.quit();
    process.exit(0);
  });
});
```

### 6.3 Deployment (10개 파드로 시작)

```yaml
# deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: chat-service
  namespace: chat-system
  labels:
    app: chat-service
spec:
  replicas: 10  # 초기 10개 파드
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 3
      maxUnavailable: 1
  selector:
    matchLabels:
      app: chat-service
  template:
    metadata:
      labels:
        app: chat-service
        version: v1
    spec:
      # 파드 분산 (AZ 간)
      topologySpreadConstraints:
      - maxSkew: 1
        topologyKey: topology.kubernetes.io/zone
        whenUnsatisfiable: DoNotSchedule
        labelSelector:
          matchLabels:
            app: chat-service
      
      # 안티 어피니티 (노드 분산)
      affinity:
        podAntiAffinity:
          preferredDuringSchedulingIgnoredDuringExecution:
          - weight: 100
            podAffinityTerm:
              labelSelector:
                matchExpressions:
                - key: app
                  operator: In
                  values:
                  - chat-service
              topologyKey: kubernetes.io/hostname
      
      containers:
      - name: chat-service
        image: <AWS_ACCOUNT_ID>.dkr.ecr.ap-northeast-2.amazonaws.com/chat-service:v1.0.0
        imagePullPolicy: Always
        ports:
        - name: http
          containerPort: 3000
          protocol: TCP
        
        # 리소스 요청/제한
        resources:
          requests:
            cpu: 500m      # 0.5 CPU
            memory: 512Mi
          limits:
            cpu: 2000m     # 2 CPU
            memory: 2Gi
        
        # 환경변수
        env:
```

```javascript
import { check } from 'k6';

export const options = {
  stages: [
    { duration: '5m', target: 10000 },   // 5분간 1만 연결
    { duration: '10m', target: 50000 },  // 10분간 5만 연결
    { duration: '10m', target: 100000 }, // 10분간 10만 연결
    { duration: '10m', target: 100000 }, // 10분 유지

    ws_msgs_received: ['count>1000000'],
  },
};

export default function () {
  const url = 'wss://chat.yourdomain.com/socket.io/?EIO=4&transport=websocket';
  
  const res = ws.connect(url, {}, function (socket) {
    socket.on('open', () => {
      console.log('Connected');
      
      // 방 참가
      socket.send(JSON.stringify({
        type: 'join-room',
        roomId: `room-${Math.floor(Math.random() * 100)}`,
      }));
      
      // 주기적 메시지 전송 (10초마다)

    });

    });

    socket.on('close', () => {

    });

    socket.setTimeout(() => {
      socket.close();
    }, 600000); // 10분 후 종료
  });
```

## 14. CI/CD 파이프라인

### 14.1 GitHub Actions 예시

```yaml
# .github/workflows/deploy.yml
name: Deploy to EKS

on:
  push:
    branches: [ main ]

env:
  AWS_REGION: ap-northeast-2
  ECR_REPOSITORY: chat-service
  EKS_CLUSTER: chat-prod

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
    - uses: actions/checkout@v3
    
    - name: Configure AWS credentials
      uses: aws-actions/configure-aws-credentials@v2
      with:
        aws-access-key-id: ${{ secrets.AWS_ACCESS_KEY_ID }}
        aws-secret-access-key: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
        aws-region: ${{ env.AWS_REGION }}
    
    - name: Login to Amazon ECR
      id: login-ecr
      uses: aws-actions/amazon-ecr-login@v1
    
    - name: Build and push image
      env:
        ECR_REGISTRY: ${{ steps.login-ecr.outputs.registry }}
        IMAGE_TAG: ${{ github.sha }}
      run: |
        docker build -t $ECR_REGISTRY/$ECR_REPOSITORY:$IMAGE_TAG .
        docker push $ECR_REGISTRY/$ECR_REPOSITORY:$IMAGE_TAG
        docker tag $ECR_REGISTRY/$ECR_REPOSITORY:$IMAGE_TAG $ECR_REGISTRY/$ECR_REPOSITORY:latest
        docker push $ECR_REGISTRY/$ECR_REPOSITORY:latest
    
    - name: Update kubeconfig
      run: |
        aws eks update-kubeconfig --name $EKS_CLUSTER --region $AWS_REGION
    
    - name: Deploy to EKS
      env:
        ECR_REGISTRY: ${{ steps.login-ecr.outputs.registry }}
        IMAGE_TAG: ${{ github.sha }}
      run: |
        kubectl set image deployment/chat-service \
          chat-service=$ECR_REGISTRY/$ECR_REPOSITORY:$IMAGE_TAG \
          -n chat-system
        kubectl rollout status deployment/chat-service -n chat-system
```
